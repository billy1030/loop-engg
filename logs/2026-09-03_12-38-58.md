# Exchange 遷移的「信心等級 (Migration Confidence Level)」完整指南

> 在 Exchange Server 遷移作業中，無論是 On-Premises 間遷移，或是 On-Premises 遷移至 Microsoft 365（Exchange Online），**Migration Confidence Level（信心等級）** 是管理者監控資料完整性的關鍵指標之一。

---

## 一、什麼是「Migration Confidence Level」？

**Migration Confidence Level**（信心等級）是一個 **0%–100% 的數值**，由移轉程序依據 **批次中已成功遷移的項目 / 該批次總項目數** 自動計算並記錄的指標，用以評估每一個遷移批次（migration batch）的整體成功度。

| 屬性 | 說明 |
|---|---|
| **數值範圍** | 0% ~ 100% |
| **顯示位置** | Exchange Admin Center (EAC) → **Migrations** 索引標籤，每個批次右側 |
| **PowerShell 查看** | `Get-MigrationBatch \| FL Identity, Status, *Confidence*, ItemCount` |
| **預設門檻** | 多數情境 95%（可調，企業實務 95%–99%） |
| **若低於門檻** | 該批次會**顯示「Auto-suspended」（自動暫停）** 需手動介入 |

---

## 二、如何查看信心等級？

### 方法 1：Exchange Admin Center (EAC)

```
1. 登入 https://admin.exchange.microsoft.com  (EAC)
2. 選「Migration」(遷移)
3. 選「Migration batches」(遷移批次)
4. 找到目標批次
5. 點選「View details」(檢視詳細資料)
6. 在「Status」欄位 → 看到 "Confidence level" 數值
```

### 方法 2：PowerShell (Exchange Online)

```powershell
# 連線至 Exchange Online
Connect-ExchangeOnline -UserPrincipalName admin@contoso.com

# 取得所有遷移批次與信心等級
Get-MigrationBatch | Format-List Identity,Status,ItemCount,ItemsSkipped,ItemsSynced,LastSyncedDate

# 詳細的信心等級欄位
Get-MigrationBatch | Format-List Identity,MigrationType,BatchName,*
```

### 方法 3：取得單一使用者的遷移信心等級

```powershell
Get-MigrationUser -BatchId "Batch01" | 
  Format-List Identity,EmailAddress,Status,ItemsMigrated,SkippedItems,ConfidenceLevel
```

> 💡 **重要提示**：在 EAC 與 Microsoft 365 Admin Center 中，**`ConfidenceLevel` 屬性只存在於某些 MigrationType**（例如 Cutover/Exchange Remote/IMAP 等），且**並非每個版本都會顯示在 UI**。PowerShell 是最可靠的查詢方式。

---

## 三、信心等級的判讀標準

| 信心等級 | 意義 | 處置 |
|---|---|---|
| 🟢 **99%–100%** | 完整遷移、誤差極低（可能僅有日誌型計數差異） | 直接進行 **Complete (完成)** 作業 |
| 🟢 **95%–98%** | 略低，可能含少量 Calendar/Contacts/Distribution Groups 細項差異 | 查詢 Skipped items 細節、評估可接受後手動 **Resume** |
| 🟡 **90%–94%** | 有值得注意的落差，需查 **SkippedItem 報告** | 建議先排除問題，必要時同步繼續 |
| 🟠 **< 90%** | 落差過大 | **不要** 完成遷移，需先診斷 |
| 🔴 **0% 或 N/A** | 連線失敗、未開始、批次未配置 | 需重新設定並啟動 |

## 四、為什麼信心等級會低於 100%？

實務上常見的跳過項目原因：

| 類型 | 原因 | 影響 |
|---|---|---|
| **損壞的郵件項目 (Corrupted Items)** | 郵件本體壞掉無法複製 | 預設略過 100 封 / 批次；可調高 `BadItemLimit` |
| **時間戳記 / 大小限制** | 信件 > 150 MB 等於 Exchange Online 上限 | 會被略過 |
| **單一執行個體訊息 (Single Instance)** | 重複的相同副本 | 計數方式差異 |
| **日曆項目差異** | 行事曆異常、已過期會議 | 被略過 |
| **隱藏 / 系統資料夾項目** | RSS Feeds、Search Folders、Quick Steps | 不納入主信箱 |
| **隱私權限** | 經 IRM 加密但權限失效 | 跳過 |
| **離線通訊錄差異** | 僅於 OAB 相關 OAB/Offline Address Book | 雲端會重建 |

## 五、查看「被跳過的項目」報告 (Skipped Items Report)

**Step 1：取得 Skipped 報告**

```powershell
# 取得目前批次的被略過項目
$batch = Get-MigrationBatch -Identity "Batch01"

# 匯出詳細跳過清單
$report = $batch | Get-MigrationUserStatistics | 
  Where-Object { $_.SkippedItems -gt 0 } |
  Select-Object Identity, SkippedItems, SkippedItemDuration

$report | Export-Csv "C:\Reports\SkippedItems_$(Get-Date -Format yyyyMMdd).csv" -NoTypeInformation
```

**Step 2：使用 CSV 報告可看出**：

- 哪些使用者被跳過
- 跳過了哪些項目數量
- 是否集中在特定使用者（提示來源信箱問題）

## 七、調高「容忍損壞項數」以避免 Batch 卡住

若要避免少量損壞郵件讓信心等級暴跌，可調整：

```powershell
# 建立時設定壞項目容忍
New-MigrationBatch -Name "Batch01" `
  -SourceEndpoint "Ex2016" `
  -TargetDeliveryDomain "contoso.mail.onmicrosoft.com" `
  -BadItemLimit 500            # 允許最多 500 封壞信件跳過
  -LargeItemLimit 50          # 超過 25MB 的信件最多 50 封跳過
  -SkipCalendar            # 暫時跳過行事曆（先確認信成功）
  -SkipContacts            # 暫時跳過通訊錄
  -AutoStart

# 對已建立的批次
Set-MigrationBatch -Identity "Batch01" -BadItemLimit 1000
```

> ⚠️ `BadItemLimit 1000` 已可容納 0.01% 的失敗率。但您先前已要求 **零郵件丟失**，實務上要**先逐用戶預演** 確認信頭完整、附件下載正常，再調高門檻。

## 八、信心等級 vs. 同步完成 ≠ 真的完成

> 🚨 **極重要觀念**：

```
Confidence Level = (成功遷移的項目) / (全部應遷移項目)

它只告訴你 "比例"，不是 "絕對資料完整性"
```

**在 Final Sync 完成後，您仍應額外檢查**：

```powershell
# 1. 信箱大小比對
Get-MailboxStatistics -Identity user@contoso.com | 
  Select-Object DisplayName,ItemCount,TotalItemSize

# 2. 信件計數比對 (比對 2016 vs 365)
$onprem = Get-MailboxStatistics -Identity user@contoso.com -Database "MBX2016" 
$online = Get-MailboxStatistics -Identity user@contoso.com
"Exchange 2016 信件數: $($onprem.ItemCount)"
"Exchange Online  信件數: $($online.ItemCount)"

# 3. 公用資料夾差異
Get-PublicFolderStatistics -Server "EX2016" 
Get-MailPublicFolder -Identity "user@contoso.com"  # 雲端
```

## 十、常見的「信心等級」誤區

| 誤區 | 正確觀念 |
|---|---|
| ❌ 「信心 95% 就完成」 | 95% 仍是**有資料沒遷移**，業務上可能不接受 |
| ❌ 「跳過 100 封沒差」 | 對個別使用者而言，那 100 封可能是**重要證據信** |
| ❌ 「調高 BadItemLimit 就好」 | 會掩蓋問題根源，建議**先查**跳過原因 |
| ❌ 「Final Sync 完成 = 100% 安全」 | 仍需手動比對 ItemCount 與 TotalItemSize |
| ❌ 「跨租使用者差異不重要」 | 對 OOO / 司法取證需求可能致命 |

## 十一、給您的場景的建議（500 人 / 零丟失 / 零停機）

基於您已設定的硬指標：

| 階段 | 信心等級目標 | 對應動作 |
|---|---|---|
| **預演測試 (Pilot)** | 100% | 5–10 個高階主管 / 關鍵帳號，先驗證流程 |
| **正式批次 1 (測試用戶擴大)** | ≥ 99% | 100 人；同步期 ≥ 7 天 |
| **正式批次 2 (核心業務)** | ≥ 99.5% | 主動調閱每個 Skipped 報告，必要時手動補搬 |
| **正式批次 3 (剩餘)** | ≥ 99.5% | 同上 |
| **最終完成 (Complete)** | 100% 或**已記錄跳過清單** | 確認不影響業務後才按下 Complete |

---

## 十二、一行總結

> 🎯 **信心等級不是「我有多少信心」，而是「這個批次跳過了多少資料」**。
> 對您的零丟失承諾而言，**95% 就是 5% 的不確定**——請在 Pilot 階段就把信心等級推到 100%，並建立「逐用戶 ItemCount 比對」報表，作為切換日 (Cutover Day) 的最終驗證。

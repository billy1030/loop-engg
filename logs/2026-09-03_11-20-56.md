### 2.1 Microsoft Entra Connect v2 安裝

**安裝步驟**（Custom 安裝以利日後分階段控管）：

1. 下載 Entra Connect v2（Microsoft 365 Admin Center → Setup → Identity → Download）
2. 在生產 Entra Connect 伺服器上執行安裝，選擇 **Custom**
3. 關鍵設定：
   - **User sign-in**：選擇 **Password Hash Synchronization** ✅（您指定）
   - 勾選 **Enable single sign-on**（Seamless SSO）
   - **Sync features**：勾選 Password writeback（選配）、Group writeback（視需要）
   - OU 篩選：僅勾選要同步的 OU（**不要同步整個網域**，特別是 Service Accounts OU）
   - 識別方法：**sourceAnchor 預設使用 mS-DS-ConsistencyGuid**（推薦，比 ObjectGUID 更穩定）

### 2.2 啟動 Password Hash Synchronization

PHS 工作原理（重要說明用於變革管理）：

> AD 將 NTLM hash 雜湊後，Entra Connect 用 **PBKDF2-HMAC-SHA256 + 1,000 次迭代 + per-user/per-tenant salt** 再次雜湊，再上傳到 Entra ID。**純文字密碼與原始 NTLM hash 永遠不離開內部**。

- 同步週期：**每 2 分鐘**自動同步密碼變更（不可調整）
- 初次啟用會對所有 in-scope 使用者執行**初始密碼同步**（500 人約 5-15 分鐘）
- 失敗會自動重試，錯誤寫入事件檢視器

**驗證指令**：

```powershell
# 確認 PHS 已啟用
Import-Module ADSync
Get-ADSyncAADPasswordSyncConfiguration

# 對單一使用者強制同步（驗證用）
Invoke-ADSyncDiagnostics -PasswordSync
```

### 2.3 部署 Entra Connect Staging Mode（高可用性）

**為何必要**：當 Active Entra Connect 故障時，可在 5 分鐘內切換到 Staging 伺服器接管，避免同步中斷。

1. 準備第二台同等規格伺服器
2. 安裝 Entra Connect，**勾選「Enable staging mode」**
3. 不勾選「Start synchronization process on completion」（之後手動啟動）
4. 同步完成後，使用 `Get-ADSyncScheduler` 確認 `StagingModeEnabled = True`
5. Staging 伺服器仍會執行 import + synchronization，但**不匯出**到 Entra ID，也**不同步密碼**

> ⚠️ **關鍵警告**：Staging 模式期間**不執行密碼同步**。若 Active 伺服器長期失效才切換，可能有密碼 backlog，需追蹤 Event ID 654/656/657 確認補齊進度。

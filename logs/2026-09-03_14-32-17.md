# iptables Rich Rules — Usage & Syntax

**Rich rules** are an advanced, human-readable way to express complex firewall policies in `firewalld`, which internally translates them into `iptables`/`nftables` rules. They give you far more granularity than simple `service`/`port` rules while still being manageable through zones.

> 📖 Full official spec: `man firewalld.richlanguage` (also at <https://firewalld.org/documentation/man-pages/firewalld.richlanguage>)

---

## 1. Management Commands

All rich rules live inside a **zone**. If `--zone=` is omitted, the default zone is used.

| Action | Command |
|---|---|
| Add (runtime) | `firewall-cmd --zone=<zone> --add-rich-rule='<rule>'` |
| Add (permanent) | `firewall-cmd --permanent --zone=<zone> --add-rich-rule='<rule>'` |
| Add with TTL | `firewall-cmd --zone=<zone> --add-rich-rule='<rule>' --timeout=10m` |
| Remove | `firewall-cmd --zone=<zone> --remove-rich-rule='<rule>'` |
| Query | `firewall-cmd --zone=<zone> --query-rich-rule='<rule>'` (exit code 0=yes, 1=no) |
| List | `firewall-cmd --zone=<zone> --list-rich-rules` |

After any `--permanent` change, run `firewall-cmd --reload` to apply.

---

## 2. Canonical Rule Structure

```
rule [family="ipv4|ipv6"]
     [priority="<−32768..32767>"]
     [source [not] address="<addr>[/<mask>]" | mac="<MAC>" | ipset="<name>"]
     [destination [not] address="<addr>[/<mask>]" | ipset="<name>"]
     <element>
     [log [prefix="<text>"] [level="<lvl>"] [limit value="<rate>/<duration>"]]
     [audit [limit value="<rate>/<duration>"]]
     <action>
```

Key ordering facts:
- If `priority` is omitted, firewalld auto-sorts rules by action (deny/reject rules go **above** allow rules).
- **Lower priority number = higher precedence.** Negative = before other zone primitives; positive = after.
- **First match wins** — later rules are not evaluated.

---

## 3. Element Types (pick exactly one)

| Element | Syntax | Notes |
|---|---|---|
| **service** | `service name="<name>"` | Use `firewall-cmd --get-services` to list |
| **port** | `port port="<n>[-<n>]" protocol="tcp\|udp\|sctp\|dccp"` | Single port or range |
| **protocol** | `protocol value="<name\|id>"` | e.g. `icmp`, `gre` (see `/etc/protocols`) |
| **icmp-block** | `icmp-block name="<type>"` | Implicit `reject` action; no explicit action allowed |
| **masquerade** | `masquerade` | Source IP can be limited; no destination |
| **forward-port** | `forward-port port="<n>" protocol="tcp\|udp" to-port="<n>" [to-addr="<ip>"]` | Implicit `accept`; no explicit action |
| **source-port** | `source-port port="<n>" protocol="tcp\|udp"` | Matches the client's source port |

---

## 4. Action Types

| Action | Meaning |
|---|---|
| `accept` | Allow the packet |
| `reject [type="<icmp\|tcp-reset>"]` | Drop and notify sender (default: `icmp-port-unreachable`) |
| `drop` | Silently discard |
| `mark set="<value>"` | Tag the packet (used with policy routing) |

---

## 5. Source / Destination Syntax

```
source [not] address="203.0.113.10"
source address="10.0.0.0/8"
source address="192.168.1.0/255.255.255.0"   # dotted-quad mask
source address="2001:db8::/64"              # IPv6 prefix only
source mac="00:11:22:33:44:55"
source ipset="my_blacklist"
```

- `not` (config file) or `invert="true"` (CLI) negates the match.
- Hostnames are **not** supported.
- MAC & `hash:mac` ipsets are family-agnostic; other ipsets must match the rule's `family`.

---

## 6. Logging & Limits

```
log prefix="FW-DROP: " level="warning" limit value="10/m"
```

- **Levels:** `emerg`, `alert`, `crit`, `error`, `warning`, `notice`, `info`, `debug`.
- **Duration units:** `s`, `m`, `h`, `d` (max `1/d`).
- `audit` sends records to `auditd` instead of syslog (`ACCEPT`/`REJECT`/`DROP`).

## 7. Practical Examples

### Allow SSH only from a specific subnet
```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" service name="ssh" accept'
```

### Rate-limit SSH (anti-brute-force)
```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule service name="ssh" accept limit value="3/m"'
```

### Drop and log a noisy network
```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule family="ipv4" source address="203.0.113.0/24" \
       log prefix="SPAM-DROP: " level="warning" limit value="20/m" drop'
```

### Reject telnet with an explicit ICMP message
```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule family="ipv4" port port="23" protocol="tcp" reject type="icmp-port-unreachable"'
```

### Port forward (DNAT) — local to another host
```bash
# First enable masquerade
firewall-cmd --permanent --zone=public --add-masquerade

firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule family="ipv4" forward-port port="80" protocol="tcp" to-port="8080" to-addr="10.0.0.5"'
```

### Allow only host A to FTP, deny rest of subnet (priority ordering)
```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule priority=10 family="ipv4" source address="192.168.0.2/32" service name="ftp" accept'

firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule priority=20 family="ipv4" source address="192.168.0.0/24" service name="ftp" reject'
```

### Blacklist via ipset
```bash
firewall-cmd --permanent --new-ipset=blacklist --type=hash:ip
firewall-cmd --permanent --ipset=blacklist --add-entry=203.0.113.50
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule source ipset=blacklist drop'
firewall-cmd --reload
```

### MAC-based allow (LAN admin machine)
```bash
firewall-cmd --permanent --zone=trusted \
  --add-rich-rule='rule source mac="00:11:22:33:44:55" accept'
```

## 9. Common Pitfalls

1. **Forgetting `--reload`** — `--permanent` rules won't take effect until you reload.
2. **Missing `family`** — required whenever `source`/`destination` addresses or `forward-port` are used.
3. **Implicit action conflicts** — `icmp-block`, `masquerade`, and `forward-port` must **not** have an explicit action.
4. **Auto-sorting surprise** — without `priority`, deny rules silently float above allow rules and "shadow" them. Use `priority` whenever order matters.
5. **Rule with both `service` and `port`** — only one element is allowed per rule.
6. **Direct rules vs. rich rules** — prefer rich rules; use `firewall-cmd --direct` only when you need raw `iptables` features (custom chains, conntrack, mangle table, etc.).
